# devassist

Локальный CLI-агент для программирования на базе **GigaChat (Sber)** — аналог
Claude Code, работающий в терминале. Читает и пишет код, выполняет команды,
ищет по кодовой базе и итеративно решает задачи через function calling.

> **Только локально.** Агент работает исключительно с файловой системой и shell.
> Единственное разрешённое сетевое взаимодействие — API GigaChat. Инструментов
> выхода в интернет (web-поиск, скачивание, `curl`/`wget`) нет — они заблокированы
> и на уровне политики shell.

## Возможности

- 📖 **Файлы**: чтение (с диапазоном строк), создание, точечное редактирование
  (поиск-замена), наглядные unified-диффы.
- 🖥 **Shell**: выполнение команд с показом stdout/stderr и кода возврата.
- 🔎 **Поиск**: по содержимому (regex, аналог `grep -rn`) и по именам файлов (glob);
  учитывает `.gitignore`.
- 🗂 **Индекс проекта** для больших кодовых баз: карта главного в проекте
  (`repo_map`), где определён класс или функция (`find_symbol`), где используется (`find_references`), дерево вызовов
  (`call_hierarchy`), куда ведёт имя в строке (`goto_definition`), оглавление файла
  или каталога с импортами (`file_outline`) — без чтения файлов целиком. Для Python
  связи уточняет [ty](https://github.com/astral-sh/ty) — локальный LSP-сервер с
  выводом типов. Строится при первом запуске в проекте и обновляется
  инкрементально (см. «Индекс проекта» ниже).
- 🔁 **Агентный цикл**: план → действие → наблюдение → коррекция, многошагово.
- ⚡ **Потоковый вывод**: ответ модели печатается по мере генерации (SSE) и сразу
  форматируется как Markdown (заголовки, списки, таблицы, подсветка кода).
  Отключается флагом `--no-stream`.
- ⌨️ **Удобный терминал**: автодополнение слеш-команд, многострочный ввод, история
  ввода между запусками, статус-строка с заполнением контекста и расходом токенов,
  индикаторы ожидания модели и работы инструментов.
- 🧠 **Контекст проекта**: дерево файлов + файлы инструкций `AGENTS.md`,
  `GIGACODE.md`, `DEVASSIST.md`, `DEVASSIST.local.md` — в корне и в подкаталогах
  (см. «Инструкции проекта» ниже). Бюджет контекста считается от окна модели,
  замеренного пробными запросами (`--test-context`; при выборе незамеренной
  модели в REPL замер предлагается).
- 🗜 **Сжатие контекста**: когда история подходит к пределу, её начало
  сворачивается в краткое содержание — длинная задача продолжается без потери
  сделанного; вручную — `/compact` (см. «Сжатие контекста» ниже).
- 🛡 **Безопасность**: песочница по корню проекта, подтверждение изменяющих и
  опасных операций, явная классификация риска; секреты не передаются
  дочерним процессам.
- 🧭 **Режимы**: ручной (всё с подтверждением), авто-правки (правки файлов без
  вопросов) и план (только исследование и план на одобрение); переключение —
  Shift+Tab, в том числе посреди работы агента (см. «Режимы» ниже).
- 🌿 **Git**: безопасное подмножество (`status`, `diff`, `log`, `add`, `commit`,
  `checkout`, `switch`, `restore`, `stash`).
- 💾 **Сохранённые чаты**: каждый диалог автоматически сохраняется в
  `.devassist/chats/`; продолжить можно из селектора чатов (`/resume`, поиск по
  мере набора) или флагами `-c`/`-r` при запуске.
- 🤖 **Суб-агенты**: подзадачу агент поручает суб-агенту со своим контекстом
  (инструмент `task`) — `explore` исследует код только на чтение, `general`
  выполняет самостоятельную подзадачу; в контекст основного агента попадает
  только отчёт. Esc — остановить суб-агента с итогом, повторный Esc — оборвать
  (см. «Суб-агенты» ниже).
- ❓ **Вопросы пользователю**: при неоднозначной задаче агент спрашивает прямо
  посреди работы (`ask_user`) — варианты с подробными описаниями, множественный
  выбор, свой ответ.
- 🛟 **Устойчивость**: повтор сетевых сбоев, 429 и 5xx с экспоненциальной
  задержкой; устойчивое к отступам сопоставление в `edit_file` с подсказкой-
  контекстом при промахе; защита от «залипания» (стоп после серии неудачных
  вызовов инструмента подряд; ненулевой код выхода команды — результат, а не
  сбой) и от зацикливания (одинаковый вызов без изменений между повторами: на
  3-м — предупреждение модели, 4-й не выполняется, ход останавливается); при
  остановке модель кратко подводит итог — что сделано и что осталось; повтор
  отклонённой вами операции не переспрашивается; Ctrl+C не ломает историю
  диалога, а уже показанная часть прерванного ответа остаётся в ней.

**Почему так:** провайдер спрятан за интерфейсом `LLMProvider`, поэтому добавление
другой модели/вендора — это один новый класс. Инструменты единообразны (pydantic-
модель параметров → автоматическая JSON-schema для function calling) и сами
описывают, как их показывать (`describe`, `Display`), поэтому новый инструмент не
требует правок ядра. Ядро общается с интерфейсом только через события
(`AgentEvents`) — UI можно заменить, не трогая агентный цикл. Подтверждения и
песочница применяются централизованно в агентном цикле.

Направление зависимостей: `cli → agent, ui, project, llm, tools`; ядро (`agent`,
`llm`, `tools`, `project`) не импортирует `ui`/`rich` — это проверяет
`tests/test_layering.py`. Подробности и дорожная карта — в
[docs/ANALYSIS.md](docs/ANALYSIS.md).

### Формат function calling GigaChat

GigaChat использует **legacy-формат `functions`** (не `tools`):
запрос содержит массив `functions` и `function_call: "auto"`; в ответе приходит
`message.function_call` с `name` и **уже распарсенным объектом** `arguments`
(не строкой), плюс непрозрачный `functions_state_id`, который возвращается вместе
с ходом ассистента. Результат инструмента отправляется сообщением с
`role: "function"`. Всё это инкапсулировано в `llm/gigachat.py`.

## Установка

Требуется Python ≥ 3.13 и [uv](https://docs.astral.sh/uv/). Зависимости описаны в
`pyproject.toml`, точные версии зафиксированы в `uv.lock`.

```bash
uv sync                 # .venv + пакет + dev-группа (pytest, ruff)
uv run devassist        # запуск из окружения проекта

# установить CLI глобально, чтобы запускать devassist в любых проектах:
uv tool install --editable .
```

**Внутренний контур / зеркало PyPI.** Адрес зеркала в репозиторий не зашит —
задайте его переменной окружения, корпоративный CA — через системное хранилище:

```bash
export UV_DEFAULT_INDEX=https://<зеркало>/simple
export UV_SYSTEM_CERTS=1        # в старых версиях uv: UV_NATIVE_TLS=1
# или явно: export SSL_CERT_FILE=/path/to/ca-bundle.pem
```

Если uv недоступен, работает и обычный `pip install -e .` (без лок-файла).

## Конфигурация (учётные данные)

Секреты не хранятся в коде. Скопируйте пример и заполните **одну** из схем:

```bash
cp .env.example .env
# отредактируйте .env: либо GIGACHAT_ACCESS_KEY, либо GIGACHAT_CERT + GIGACHAT_KEY
```

### Две схемы авторизации

Схема выбирается **автоматически** по наличию реквизитов:

1. **OAuth по ключу (внешний контур / интернет).** Задан `GIGACHAT_ACCESS_KEY` —
   Basic-ключ обменивается на Bearer-токен (с авто-refresh). Эндпоинт по умолчанию
   — `https://gigachat.devices.sberbank.ru/api/v1`.
2. **mTLS по сертификату (внутренний контур).** Ключ не задан, но заданы
   `GIGACHAT_CERT` и `GIGACHAT_KEY` — клиент предъявляет сертификат на TLS-уровне,
   токен и заголовок `Authorization` не нужны. Эндпоинт по умолчанию —
   `https://gigachat-ift.sberdevices.delta.sbrf.ru/v1`.

Если задан `GIGACHAT_ACCESS_KEY`, используется схема OAuth (она в приоритете).
Явный `GIGACHAT_URL` всегда перекрывает URL по умолчанию.

Ключевые переменные (`.env` или окружение):

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `GIGACHAT_ACCESS_KEY` | Basic-ключ (base64 `client_id:client_secret`) — схема **OAuth** | — |
| `GIGACHAT_CERT` | путь к клиентскому сертификату (PEM) — схема **mTLS** | — |
| `GIGACHAT_KEY` | путь к приватному ключу — схема **mTLS** | — |
| `GIGACHAT_URL` | базовый URL API (перекрывает дефолт схемы) | по схеме |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` / `_B2B` / `_CORP` (только OAuth) | `GIGACHAT_API_PERS` |
| `GIGACHAT_MODEL` | модель | `GigaChat-3-Ultra` |
| `GIGACHAT_VERIFY_SSL` | проверка TLS-сертификата сервера (выключенная — предупреждение в REPL: Basic-ключ можно перехватить подменой сервера) | `0`; `1`, если задан `GIGACHAT_CA_BUNDLE` |
| `GIGACHAT_CA_BUNDLE` | корневой сертификат для проверки сервера (PEM; для API Сбера — сертификат Минцифры); включает проверку TLS | — |
| `GIGACHAT_TIMEOUT` | таймаут HTTP-запросов, с | `120` |
| `DEVASSIST_TEMPERATURE` | температура генерации (0–2) | `0.2` |
| `DEVASSIST_CONTEXT_TOKENS` | явный бюджет контекста (оценка в токенах). Без него бюджет считается от замеренного окна модели | по окну модели |
| `DEVASSIST_AUTO_COMPACT` | автоматически сжимать историю у предела контекста (`0` — только `/compact`; сверх бюджета старое отбрасывается) | `1` |
| `DEVASSIST_COMPACT_THRESHOLD` | порог автосжатия — % бюджета истории (10–95) | `80` |
| `DEVASSIST_MODE` | начальный режим: `manual`, `edits`, `plan` (см. «Режимы»; `--mode` перекрывает) | `manual` |
| `DEVASSIST_SAVE_CHATS` | сохранять чаты в `.devassist/chats/` (`0` — не сохранять, как `--no-save`) | `1` |
| `DEVASSIST_AUTO_MEASURE` | предлагать замер окна незамеренной модели (`0` — только `--test-context`) | `1` |
| `DEVASSIST_TY` | точная навигация по Python через ty (`0` — только индекс проекта, см. «Индекс проекта») | `1` |
| `DEVASSIST_SUBAGENT_MAX_STEPS` | лимит шагов одного запуска суб-агента (см. «Суб-агенты») | `25` |
| `DEVASSIST_SUBAGENT_MAX_TOKENS` | бюджет оплаченных токенов одного запуска суб-агента | `300000` |
| `DEVASSIST_SUBAGENT_TIMEOUT` | лимит времени одного запуска суб-агента, с | `600` |
| `DEVASSIST_TEST_MODEL` | модель для live-тестов | `GigaChat-2-Max` |

Приоритет источников: аргументы CLI → переменные окружения → `.env` в корне
проекта → `.env` в текущей папке → значения по умолчанию. Значения из `.env`
**не** попадают в окружение процесса, а переменные `GIGACHAT_*` вычищаются из
окружения команд, которые запускает агент, — модель не может прочитать ключ
через `env`.

> Нужна **минимум одна** схема: либо `GIGACHAT_ACCESS_KEY`, либо пара
> `GIGACHAT_CERT` + `GIGACHAT_KEY`. Иначе клиент завершится с понятной ошибкой.

> **О моделях.** Приоритетная модель — `GigaChat-3-Ultra` (значение по умолчанию).
> Если она недоступна на вашем ключе, выберите доступную через `--model` или
> `GIGACHAT_MODEL`. Список доступных чат-моделей: `devassist --list-models`.
> Live-тесты по умолчанию используют заведомо доступную `GigaChat-2-Max`.

### Окно контекста модели

API не сообщает размер окна, а в контуре развёрнуты и open-source модели с
произвольными окнами, поэтому devassist **замеряет** окно сам: отправляет модели
текст заданного размера с ответом в один токен (`max_tokens: 1`) и ищет предел.
Запросы, не уместившиеся в окно, отклоняются до генерации и, как правило, не
тарифицируются; обычно окно находится за одну оплачиваемую пробу размером с само
окно (если сервер называет лимит в тексте ошибки, как vLLM, — тоже). Записывается
консервативный результат — наибольший **подтверждённый** размер запроса по данным
API (`prompt_tokens`), с точностью ~2%. Максимум замера — 256K: если проходит
запрос такого размера, окно считается равным 256K.

- `devassist --test-context <модель>` — замерить (или перемерить) и выйти,
  с выводом каждой пробы;
- при запуске REPL, `/model <имя>` и продолжении чата с другой моделью замер окна
  незамеренной модели **предлагается**: пробы оплачиваются, поэтому без `-y`
  devassist спрашивает (отказ — до конца сессии окно считается равным 32K,
  Esc/Ctrl+C отменяет начатый замер). Одноразовый режим (`-p`) и REPL без
  терминала не замеряют — только подсказка про `--test-context`;
  `DEVASSIST_AUTO_MEASURE=0` отключает и вопрос;
- результаты лежат в `~/.devassist/models.json` (общий для всех проектов, ключ —
  имя модели, у записи — эндпоинт `base_url`: замер другого контура не
  используется) — удалите запись, чтобы замерить заново.

Бюджет запроса — 90% от «окно минус 8K на ответ»; бюджет истории — он же за
вычетом системного промпта и схем инструментов. `DEVASSIST_CONTEXT_TOKENS` задаёт
бюджет запроса явно — тогда окно не замеряется. Как история укладывается в
бюджет — см. «Сжатие контекста».

## Использование

```bash
# интерактивный REPL (клавиши и статус-строка — см. «Интерфейс» ниже)
devassist
#   В REPL: /help, /model <имя>, /mode [режим], /clear, /compact, /resume, /index [rebuild], /exit

# начать в режиме планирования (или edits — правки без вопросов)
devassist --mode plan

# продолжить последний чат / выбрать чат из списка / по id
devassist -c
devassist -r
devassist -r 20261009-1430
devassist -c -p "теперь добавь тесты"   # одноразовый запрос в продолжение чата

# не сохранять этот чат
devassist --no-save

# одноразовый запрос
devassist -p "найди все TODO в проекте и выведи список"

# выбор модели и каталога проекта
devassist -m GigaChat-2-Max -C ./my-project

# авто-подтверждение операций, кроме опасных (rm -rf, git reset --hard…)
devassist -y -p "переименуй переменную foo в bar во всех .py файлах"
# … и опасных тоже (осторожно!)
devassist --yes-all -p "очисти build/ и пересобери"

# отключить потоковый вывод (ответ целиком в конце)
devassist --no-stream -p "что делает этот проект?"

# список доступных чат-моделей
devassist --list-models

# замерить окно контекста модели (результат — в ~/.devassist/models.json)
devassist --test-context GigaChat-2-Max
```

Можно запускать и как модуль: `python -m devassist ...`.

Коды возврата одноразового режима: `0` — успех, `1` — ошибка конфигурации
(или чат для `--resume` не найден) или внутренняя ошибка,
`2` — ошибка обращения к GigaChat, `3` — ход остановлен ограничителем (лимит
шагов, серия ошибок, зацикливание: задача, скорее всего, не выполнена),
`130` — прервано (Ctrl+C).

### Интерфейс

- Ответ модели форматируется как Markdown прямо во время генерации: готовые блоки
  печатаются окончательно, ещё растущий блок перерисовывается внизу экрана.
- Пока модель думает или работает инструмент (например, долгий `pytest`), внизу
  крутится индикатор с прошедшим временем. Длинный вывод команд показывается
  сокращённо (начало и конец) — модель при этом получает его полностью.
- Под строкой ввода — статус: модель, режим (`ручной`, `⏵⏵ авто-правки`,
  `⏸ план`), заполнение контекста (жёлтый от 50%,
  красный от 80% бюджета — от окна модели или `DEVASSIST_CONTEXT_TOKENS`),
  потрачено токенов за сессию,
  предупреждение о режиме `-y`. Индикатор во время хода тоже показывает режим. После каждого хода — итог: шаги, инструменты,
  время, токены.

| Клавиша | Действие |
|---|---|
| Enter | отправить |
| `\` + Enter, Alt+Enter | новая строка (вставка многострочного текста не отправляет его) |
| `/`, Tab | меню слеш-команд с описаниями; после `/model ` — меню доступных моделей с их окнами (поиск по части имени) |
| ↑ ↓, → | история ввода, принять подсказку из истории |
| Shift+Tab | сменить режим: ручной → авто-правки → план (и во время ответа; при открытом меню команд — назад по меню) |
| Esc | во время ответа или работы инструмента — прервать ход (как Ctrl+C); во время суб-агента — остановить его с итогом, повторный Esc — оборвать |
| Esc Esc | очистить ввод (черновик остаётся в истории — ↑ вернёт его) |
| Ctrl+C | на приглашении — сбросить ввод, во время ответа — прервать ход (в том числе с суб-агентом) |
| Ctrl+D, `/exit` | выход |

Alt+Enter доходит не во всех терминалах (в Windows Terminal он переключает
полноэкранный режим, в macOS Terminal нужна опция «Use Option as Meta key») —
надёжный способ перенести строку — `\` в конце и Enter.

Пока агент работает, можно набирать следующий запрос: текст не мешает выводу и
появится в строке ввода, когда ход закончится. Esc прерывает ход и запущенную
команду так же, как Ctrl+C; на время вопроса о подтверждении ввод работает обычно.

### Режимы

Режим определяет, что агент делает сам, а что — только с вашего согласия:

| Режим | Правки файлов (`write_file`, `edit_file`) | Команды (`run_shell`) | Изменяющий `git` |
|---|---|---|---|
| **ручной** (`manual`, по умолчанию) | с подтверждением | с подтверждением | с подтверждением |
| **авто-правки** (`edits`) | без вопросов | с подтверждением | с подтверждением |
| **план** (`plan`) | запрещены | с подтверждением | запрещён |

Чтение, поиск и навигация по коду разрешены всегда.

- **Переключение:** Shift+Tab — следующий режим по кругу, и на приглашении, и пока
  агент работает (действует со следующего вызова инструмента); `/mode <режим>` или
  `/mode` — показать текущий; при запуске — `--mode` или `DEVASSIST_MODE`. Режим
  сохраняется до конца сессии (`/clear` и `/resume` его не меняют).
- **План.** Агент исследует код и, когда план готов, вызывает `exit_plan_mode`:
  план показывается в рамке, ниже — меню «Да, правки без вопросов» / «Да, с
  подтверждением» / «Свой ответ…». После одобрения режим меняется на выбранный, и
  агент сразу приступает к выполнению в том же ходе. Свой ответ — замечания: агент
  доработает план и предложит снова; Esc — не одобрять (агент остановится и
  подождёт). Попытки правок в режиме плана блокируются, а серия таких попыток
  останавливает ход. В одноразовом режиме без терминала одобрить план некому —
  агент выводит его итоговым ответом.
- **С `-y`** подтверждения отключены во всех режимах, кроме опасных команд
  (`rm -rf`, `sudo`, `git reset --hard`, принудительный `git push`…): о них
  devassist спрашивает всегда, а без терминала — отклоняет. Без вопроса их выполняет
  только явный `--yes-all`. Запреты режима плана действуют в любом случае.
- **«a» в подтверждении** — «да, и больше не спрашивать до конца сессии»: для
  правки файла — включает режим авто-правок, для команды или `git` — разрешает
  именно этот вызов (с теми же аргументами). Для опасных операций не предлагается.

**Вопросы агента.** Когда задача неоднозначна, агент может спросить
(инструмент `ask_user`, до 4 вопросов за раз). Для каждого показывается
«Вопрос i из N», текст вопроса и варианты с подробными описаниями; последний пункт —
«Свой ответ…»: выберите его и печатайте прямо в меню. ↑↓ — выбор, цифра — выбрать
сразу, Пробел — отметить (если можно выбрать несколько), Enter — ответить, Esc —
отказаться (агент решит сам и назовёт допущения). Ответы остаются в ленте одной
строкой. Если ввод не с клавиатуры, агент получает «спросить некого» и решает сам.

### Суб-агенты

Подзадачу агент может поручить суб-агенту (инструмент `task`): тот работает в
**своём** контексте — с отдельной историей, своим системным промптом и набором
инструментов — и возвращает основному агенту только итоговый отчёт. Так широкое
исследование (десятки поисков и чтений) не засоряет контекст основной задачи.

| Агент | Инструменты | Для чего |
|---|---|---|
| `explore` | чтение, поиск, навигация по индексу, `git status/diff/log/show` | исследование кода; любые изменения заблокированы в любом режиме и даже с `--yes-all` |
| `general` | все, кроме `task`, `ask_user`, `exit_plan_mode` | самостоятельная многошаговая подзадача; правки и команды — по правилам текущего режима |

- **Что видно.** Под вызовом `task` — шаги суб-агента одной строкой (`○ read_file a.py`),
  его неудачи и правки; индикатор показывает, чем он занят. Текст суб-агента не
  печатается — отчёт получает основной агент и пересказывает главное. В отчёт
  devassist сам дописывает изменённые файлы, прочие изменяющие операции (команды,
  изменяющий `git`) и отклонённые вами операции.
- **Разрешения** — общие с основным агентом: режим (Shift+Tab действует сразу и на
  суб-агента), «a — не спрашивать», `-y`. Подтверждения суб-агента задаются вам как
  обычно. Спросить вас (`ask_user`) суб-агент не может — он принимает допущения и
  называет их в отчёте. Запускать суб-агентов суб-агент тоже не может.
- **Остановка.** Esc — суб-агент прерывает текущий запрос или команду и одним
  запросом подводит итог (что успел выяснить и сделать); основной агент получает
  частичный отчёт и продолжает. Повторный Esc (пока подводится итог) обрывает
  суб-агента без отчёта — основной агент узнает, что тот успел изменить. Ctrl+C
  останавливает весь ход.
- **Ограничители.** У суб-агента действуют все ограничители хода (серия ошибок,
  повтор одного вызова) и свои: лимиты шагов, оплаченных токенов и времени
  (`DEVASSIST_SUBAGENT_MAX_STEPS`/`_MAX_TOKENS`/`_TIMEOUT`), «топтание на месте» —
  похожие вызовы с той же целью (один файл разными диапазонами, один шаблон): на
  5-м — предупреждение, на 7-м — остановка. С 70% любого лимита модель получает
  напоминание сворачиваться и не начинать новых направлений. На любой остановке
  суб-агент подводит итог, а отчёт помечается как неполный. За один ход основной
  агент запускает не больше 8 суб-агентов. Отчёт ограничен 8 000 символов.
- Токены суб-агента входят в расход хода и сессии; размер контекста основного
  агента они не увеличивают. История суб-агента не сохраняется — в чате остаётся
  его отчёт.

### Сохранённые чаты

Диалог сохраняется после каждого хода — и после прерванного (Esc/Ctrl+C) тоже —
в `.devassist/chats/<id>.json`, по файлу на чат. Id начинается с даты и времени
начала чата (`20261009-143012-a1b2c3d4`), заголовок — первый запрос.

- `/resume` (или `/chats`) открывает селектор: последние чаты со временем и числом
  запросов, у выбранного — начало последнего ответа, id и модель. ↑↓ — выбор,
  PgUp/PgDn, Home/End — быстрые переходы, печать — поиск по заголовку и ответу,
  Enter — открыть, Esc — отмена. После выбора показывается последний обмен
  репликами, и разговор продолжается с того же места (дальнейшие ходы дописываются
  в этот же чат).
- `/resume <id>` — сразу, по id или его началу (`/resume 20261009-14`).
- `/clear` начинает новый чат; прежний остаётся сохранённым.
- При запуске: `-c`/`--continue` — последний чат, `-r`/`--resume` — селектор,
  `-r <id>` — конкретный. Работает и с `-p`.
- Не сохранять: `--no-save` или `DEVASSIST_SAVE_CHATS=0`. Если записать не удалось
  (например, проект только для чтения), devassist один раз предупредит и продолжит
  работу без сохранения.

Модель — часть чата: смена через `/model` сразу сохраняется в чат, а при
продолжении (`/resume`, `-c`, `-r`) становится текущей модель чата; явный `-m`
при запуске её перекрывает. Краткое содержание сжатой истории тоже сохраняется:
продолжение сжатого чата видит его, а не старые сообщения (сам журнал в файле
полный). Системный промпт не сохраняется — при продолжении контекст проекта
собирается заново. Если один и тот же чат продолжить в двух
окнах сразу, сохранится версия того, кто ответил последним.

Если вывод перенаправлен (`devassist -p … > answer.md`) или ввод идёт не с
терминала, интерактивных элементов нет: ответ печатается как есть, сырым Markdown.

### Сжатие контекста

Окно модели конечно, а длинная задача (десятки чтений файлов и запусков тестов)
быстро его заполняет. Когда история занимает 80% бюджета истории
(`DEVASSIST_COMPACT_THRESHOLD`), перед очередным обращением к модели devassist
сворачивает её начало в **краткое содержание**: модель отдельным запросом без
инструментов пересказывает старую часть — запросы и решения пользователя,
изменённые файлы и суть правок, итоги команд и тестов, найденные факты, текущее
состояние и следующие шаги. Дальше модель видит это краткое содержание (в
системном сообщении) и свежие сообщения.

- Свежие сообщения (~25% бюджета истории) остаются дословно, текущий запрос — тоже,
  даже если сжатие пришлось на середину хода; вызов инструмента и его результат
  не разделяются.
- Повторное сжатие обновляет прежнее краткое содержание; очень длинная история
  пересказывается по частям (на вход идут три последних куска размером с окно и
  всегда — последний запрос пользователя).
- Пока идёт сжатие, внизу крутится индикатор; итог — строка «✂ контекст сжат:
  ~24k → ~6.5k ток.». Токены суммаризации входят в «потрачено». Esc/Ctrl+C во
  время автосжатия прерывает весь ход; история при этом не меняется.
- Если сжать не удалось (ошибка сети, пустой ответ), devassist предупредит и до
  конца хода не повторяет попытку — старые сообщения, не помещающиеся в бюджет,
  просто отбрасываются (текущий запрос — никогда). Так же история укладывается в
  бюджет при `DEVASSIST_AUTO_COMPACT=0`.
- `/compact [пожелания]` — сжать весь диалог сейчас, например перед сменой темы:
  `/compact сохрани список изменённых файлов`. Esc отменяет, история не меняется.
- Журнал чата не переписывается: `/resume` показывает настоящий последний обмен,
  а в файле чата лежат все сообщения и краткое содержание.

### Инструкции проекта

Соглашения проекта, команды сборки и заметки для агента кладутся в файлы
инструкций — их содержимое добавляется в контекст. Поддерживаются (по
возрастанию приоритета):

| Файл | Для чего |
|---|---|
| `AGENTS.md` | общий формат инструкций для разных ИИ-агентов |
| `GIGACODE.md` | инструкции GigaCode |
| `DEVASSIST.md` | инструкции именно для devassist |
| `DEVASSIST.local.md` | личные заметки (добавьте в `.gitignore`) |

При противоречии важнее файл ниже в таблице; ваши указания в диалоге важнее
любых файлов. Один и тот же файл под двумя именами (симлинк
`DEVASSIST.md → AGENTS.md`) читается один раз. Лимиты: 20 000 символов на файл и
30 000 на все файлы каталога — при нехватке место получают приоритетные, а не
поместившийся файл агент видит как ссылку и может прочитать сам.

**Подкаталоги.** Те же файлы можно положить в любой каталог (`services/api/AGENTS.md`)
— они действуют для его файлов и важнее инструкций корня. Инструкции корня в
контексте всегда, а инструкции подкаталога подключаются, когда агент впервые
успешно работает с путём внутри него (читает, правит, смотрит каталог или
оглавление): devassist сообщает «подключены инструкции подкаталога: …», и с этого
момента они в системном сообщении (до `/clear` или `/resume`) — их не вытесняет
ни обрезка, ни сжатие истории. Инструкции из `node_modules`, `.devassist` и
каталогов, исключённых `.gitignore`, не подключаются.

### Индекс проекта

Чтобы на большой кодовой базе не читать файлы целиком, агент держит индекс
проекта: список файлов и определения в них — классы, функции, методы, типы,
константы, заголовки Markdown. Python разбирается модулем `ast` (вложенность,
диапазоны строк, первая строка докстринга), JS/TS, Go, Rust, Java, Kotlin, C#, Ruby,
PHP, C/C++, shell, Scala и Swift — [tree-sitter](https://tree-sitter.github.io/)
(грамматики — колёса `tree-sitter-<язык>`, офлайн): определения с диапазонами строк
и вложенностью (метод — внутри класса) и вызовы. Python-файл, который `ast` не
разобрал (синтаксическая ошибка посреди правки, синтаксис новее интерпретатора),
тоже разбирается tree-sitter; построчные шаблоны остались запасным путём, если
грамматика не загрузилась.

Для Python индекс знает ещё **использования** — вызовы, обращения к атрибутам и
упоминания имён с функцией или классом, где они встречаются (для остальных языков —
вызовы), — и **импорты**,
сопоставленные с файлами проекта (абсолютные и относительные, в том числе при
раскладке `src/`). Использования ищутся по имени, без вывода типов, поэтому
результат ранжируется: сначала файлы, импортирующие модуль определения (и
псевдонимы `import … as …`), затем сам файл определения, затем совпадения только по
имени. Параметры и локальные переменные функций, `self`/`cls`, встроенные имена и
имена из одного символа не учитываются.

- **Построение.** При запуске REPL в git-репозитории без индекса (или с
  недостроенным) индекс строится до первого ввода — с индикатором «индексирую
  проект: N файлов». Вне git-репозитория (например, в домашнем каталоге)
  автоматически не строится — `/index` или инструменты построят его по запросу.
  Esc или Ctrl+C отменяет построение: сессия продолжается, уже сделанное
  сохраняется и достраивается при следующем запуске. Одноразовый режим (`-p`)
  индекс заранее не строит — его построят инструменты при первом обращении.
- **Обновление.** Перед каждым запросом к индексу перечитываются только файлы с
  изменившимися размером или временем изменения, поэтому правки (в том числе
  самого агента) видны сразу. `/index` — обновить и показать состав индекса,
  `/index rebuild` — перестроить с нуля.
- **Что не индексируется:** файлы из `.gitignore` и служебных каталогов
  (`.git`, `node_modules`, `.venv`…), `.env*`; файлы больше 1 МБ и бинарные
  попадают в список без разбора содержимого.
- **Инструменты агента:** `find_symbol` — где определено имя (`Agent`,
  `Agent.run_turn`, фильтры по виду и glob); `find_references` — использования
  определения, сгруппированные по файлам (фильтры: `call`, `attr`, `name`,
  `import`, glob); `call_hierarchy` — кто вызывает функцию или что вызывает она
  сама, на глубину до 3; `goto_definition` — куда ведёт имя в строке файла и его
  тип; `file_outline` — оглавление файла с номерами строк (для Python — что файл
  импортирует из проекта и где импортируется сам) или сводка по каталогу;
  `repo_map` — карта проекта (см. ниже).

#### Карта проекта

Карта — самые важные определения проекта с сигнатурами и номерами строк, в
пределах заданного объёма. Важность считается как у
[Aider](https://aider.chat/docs/repomap.html): граф «файл, где имя используется →
файл, где оно определено», персонализированный PageRank; сильнее весят длинные
составные имена и имена из фокуса, слабее — `_приватные`, определённые во многих
файлах и совпадающие с методами встроенных типов (`get`, `items`). Метод
показывается вместе со своим классом, пропущенное в файле — строкой «⋮ ещё N».

- **В системном промпте** — когда проект крупный и дерево файлов обрезано, а индекс
  уже построен (около 6 000 символов). Промпт индекс не строит.
- **Инструмент `repo_map`** — карта под задачу: `focus` — файлы, каталоги и имена,
  с которыми идёт работа (связанное с ними поднимается выше), `max_tokens` — объём.

#### Точная навигация по Python: ty

Индекс находит использования по имени. Для Python связи уточняет
[ty](https://github.com/astral-sh/ty) (Astral, MIT) — LSP-сервер с выводом типов,
ставится вместе с devassist (`ty` в зависимостях) и работает локально, без сети.
`find_references` помечает подтверждённые ty использования «точно (ty)» и ставит
их первыми; `goto_definition` и `call_hierarchy` отвечают через ty целиком (с учётом
импортов, псевдонимов и типа объекта: `obj.method()`).

- **Запуск.** `ty server` стартует при первом запросе к этим инструментам и живёт
  до конца сессии; лог — `.devassist/ty.log`. Сервер работает в своей группе
  процессов (Ctrl+C его не прерывает) и не получает переменных `GIGACHAT_*`.
- **Свежесть.** За файлами ty сам не следит: перед каждым запросом обновляется
  индекс, и ty получает список добавленных, изменённых и удалённых файлов — правки,
  в том числе самого агента, видны сразу.
- **Сбои.** Если ty упал или не ответил, запрос выполняется по индексу (с пометкой
  в ответе), сервер перезапускается; после второго сбоя ty отключается до конца
  сессии. Состояние ty показывает `/index`.
- **Ограничения.** ty в бета-версии (`0.0.x`), версия зафиксирована точно. Ссылки ty
  не проходят через псевдонимы импорта (`from m import f as g` → вызовы `g()`) —
  их находит индекс. `DEVASSIST_TY=0` выключает ty — останется только индекс.

`.gitignore` учитывается и в `find_files`, `search_content` и дереве проекта в
системном промпте: вложенные `.gitignore`, отрицания `!`, `.git/info/exclude`.
Не читаются `.gitignore` выше корня проекта и глобальный `core.excludesFile`.

### Служебная папка `.devassist/`

Рабочие данные агента хранятся в `.devassist/` в корне проекта: история ввода
REPL (`history`), индекс проекта (`index/`) и сохранённые чаты (`chats/`).
История и чаты содержат всё, что вы вводили и что агент прочитал или получил из
команд, — включая случайно попавшие туда секреты; файлы чатов создаются с правами
только для владельца. Папка создаётся автоматически при первой записи и содержит
собственный `.gitignore` со `*` — её содержимое не попадает в репозиторий.
Инструменты `write_file`/`edit_file` в неё не пишут.

Замеренные окна моделей хранятся отдельно — в `~/.devassist/models.json` в
домашней папке: окно — свойство модели, а не проекта.

## Тестирование

Все тесты запускаются одной командой:

```bash
uv run pytest      # или: make test-all
```

- **Юнит-тесты инструментов** (без сети) — быстрые, выполняются всегда: на каждый
  инструмент (чтение/запись/редактирование/поиск/shell/git) и на песочницу.
- **Live-тесты LLM** (маркер `live`) — реально обращаются к GigaChat и проверяют
  все типы вызовов: простой запрос-ответ, одиночный tool call, многошаговый диалог
  с возвратом результата инструмента в модель.
- **Сквозной smoke-тест** — гоняет агент на настоящей мини-задаче (создать файл →
  отредактировать → выполнить команду) от начала до конца.

Live-тесты автоматически **пропускаются**, если реквизиты GigaChat не заданы
(ключ или пара cert+key в окружении либо в `.env` репозитория). Запуск только
офлайн- или только live-тестов:

```bash
uv run pytest -m "not live"   # быстрые офлайн-тесты (make test)
uv run pytest -m live         # только живые (нужен ключ; медленнее)
```

## Модель безопасности

- **Песочница**: любые файловые операции ограничены корнем проекта; выход за его
  пределы (`../`, абсолютные пути, симлинки) отклоняется. В служебную папку
  `.devassist/` (чаты, история ввода) и в `.git/` `write_file`/`edit_file` не пишут.
- **Подтверждения**: изменяющие операции (`write_file`, `edit_file`, `run_shell`,
  пишущий `git`) требуют подтверждения; опасные shell-команды (`rm -rf`, `sudo`,
  `git reset --hard`, сетевые загрузки и т.п.) помечаются отдельно. Режим
  авто-правок снимает подтверждение только с правок файлов, режим плана запрещает
  правки и изменяющий `git` (`permissions.decide`). Флаг `-y`
  отключает запросы, кроме опасных операций; `--yes-all` — и их (используйте
  осознанно). Операция, которую невозможно
  выполнить (путь вне проекта, запрещённая подкоманда), отклоняется до запроса
  подтверждения.
- **Процессы**: команды запускаются без доступа к терминалу (stdin пуст), в
  отдельной группе процессов, которая целиком останавливается по таймауту
  (1–600 с), по Ctrl+C и если фоновые потомки (`cmd &`) продолжают работать после
  выхода команды. Из окружения удаляются `GIGACHAT_*`.
- **Git**: опции `--output`, `--no-index`, `--ext-diff`, `--pathspec-from-file`
  запрещены (запись/чтение вне проекта); `branch` без подтверждения — только
  просмотр веток; редактор не открывается (для `commit` нужен `-m`). git
  запускается с `core.fsmonitor=false` и `safe.bareRepository=explicit`, а
  `diff`/`log`/`show` — с `--no-ext-diff`: настройки репозитория не запускают
  внешние программы на просмотре.
- **Суб-агенты**: подтверждения и режим — общие с основным агентом; `explore`
  ничего не меняет ни в каком режиме (`permissions.decide(read_only=True)`), без
  вопросов пользователю и без вложенных суб-агентов; лимиты шагов, токенов и
  времени на каждый запуск.
- **Поиск**: `search_content` не читает `.env*` (кроме `.env.example`) — ни
  напрямую, ни через симлинки, — а также бинарные файлы и файлы больше 1 МБ;
  `find_files` не принимает шаблоны с `..` и абсолютные пути. Индекс проекта
  не хранит `.env*`.
- **Служебная папка и git**: `write_file`/`edit_file` не пишут в `.devassist/`
  (индекс, история ввода) и во внутренности git — `.git/` на любой глубине, в
  любом регистре, а также каталог из `gitdir:` `.git`-файла. Иначе правка
  `.git/config` (`core.fsmonitor`, `diff.external`) превращала бы `git status`
  или `git diff`, которые выполняются без вопроса, в запуск произвольной команды
  — в том числе в режиме авто-правок. Отказ — ещё до запроса подтверждения.
```
