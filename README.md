# devassist

Локальный CLI-агент для программирования на базе **GigaChat (Sber)** — аналог
Claude Code, работающий в терминале. Читает и пишет код, выполняет команды,
ищет по кодовой базе и итеративно решает задачи через function calling.

> **Только локально.** Агент работает исключительно с файловой системой и shell.
> Единственное разрешённое сетевое взаимодействие — API GigaChat. Инструментов
> выхода в интернет (web-поиск, скачивание, `curl`/`wget`) нет — они заблокированы
> и на уровне политики shell.

## Возможности

- 📖 **Файлы**: чтение (с диапазоном строк), создание, точечное редактирование
  (поиск-замена), наглядные unified-диффы.
- 🖥 **Shell**: выполнение команд с показом stdout/stderr и кода возврата.
- 🔎 **Поиск**: по содержимому (regex, аналог `grep -rn`) и по именам файлов (glob).
- 🔁 **Агентный цикл**: план → действие → наблюдение → коррекция, многошагово.
- ⚡ **Потоковый вывод**: ответ модели печатается по мере генерации (SSE) и сразу
  форматируется как Markdown (заголовки, списки, таблицы, подсветка кода).
  Отключается флагом `--no-stream`.
- ⌨️ **Удобный терминал**: автодополнение слеш-команд, многострочный ввод, история
  ввода между запусками, статус-строка с заполнением контекста и расходом токенов,
  индикаторы ожидания модели и работы инструментов.
- 🧠 **Контекст проекта**: дерево файлов + файлы инструкций `DEVASSIST.md` и
  `DEVASSIST.local.md`; история укладывается в бюджет контекста без потери
  текущей задачи.
- 🛡 **Безопасность**: песочница по корню проекта, подтверждение изменяющих и
  опасных операций, явная классификация риска; секреты не передаются
  дочерним процессам.
- 🌿 **Git**: безопасное подмножество (`status`, `diff`, `log`, `add`, `commit`,
  `checkout`, `switch`, `restore`, `stash`).
- 🛟 **Устойчивость**: повтор сетевых сбоев, 429 и 5xx с экспоненциальной
  задержкой; устойчивое к отступам сопоставление в `edit_file` с подсказкой-
  контекстом при промахе; защита от «залипания» (стоп после серии неудачных
  вызовов инструмента подряд); Ctrl+C не ломает историю диалога.

```

  errors.py          общие исключения (ToolError, SandboxError)
  security.py        песочница путей + классификация риска команд
  project/           знание о проекте (без LLM и UI)
    workspace.py     корень проекта и служебная папка .devassist/ (создаётся лениво)
    files.py         единые правила игнорирования, обход файлов, glob, дерево
    instructions.py  файлы инструкций проекта (DEVASSIST.md, DEVASSIST.local.md)
  llm/
    base.py          абстрактный LLMProvider + LLMError (легко добавить провайдера)
    gigachat.py      GigaChat: OAuth (авто-refresh) или mTLS, chat, function calling, SSE
    types.py         Message / ToolSpec / FunctionCall / Usage (pydantic)
  tools/
    base.py          Tool ABC (describe/preview/run), Display, реестр, JSON-schema
    process.py       безопасный запуск процессов (stdin, группа процессов, окружение)
    fs.py            read/write/edit_file, list_dir, find_files
    search.py        search_content (grep)
    shell.py         run_shell
    git.py           git
  agent/             ядро — не зависит от UI
    loop.py          агентный цикл и оркестрация инструментов
    events.py        протокол событий для UI (AgentEvents)
    conversation.py  история диалога (сериализуемая)
    context_window.py оценка токенов и окно истории под бюджет
    guard.py         ограничители цикла (лимит шагов, серия ошибок)
    prompts.py       системный промпт + контекст проекта
  ui/
    theme.py         палитра, иконки, стили Markdown и строки ввода
    console.py       терминальный UI (rich), реализует AgentEvents; временная область
    markdown.py      Markdown в стиле devassist
    markdown_stream.py потоковый Markdown: окончательные блоки + растущий хвост
    format.py        числа токенов, склонения, сокращение длинного вывода
  cli/
    app.py           точка входа, сборка компонентов, коды возврата
    repl.py          интерактивный режим
    prompt.py        строка ввода (prompt_toolkit): автодополнение, история, статус
    commands.py      реестр слеш-команд
tests/               офлайн-тесты + live-тесты LLM + сквозной smoke
docs/ANALYSIS.md     анализ кодовой базы и дорожная карта
```

**Почему так:** провайдер спрятан за интерфейсом `LLMProvider`, поэтому добавление
другой модели/вендора — это один новый класс. Инструменты единообразны (pydantic-
модель параметров → автоматическая JSON-schema для function calling) и сами
описывают, как их показывать (`describe`, `Display`), поэтому новый инструмент не
требует правок ядра. Ядро общается с интерфейсом только через события
(`AgentEvents`) — UI можно заменить, не трогая агентный цикл. Подтверждения и
песочница применяются централизованно в агентном цикле.

Направление зависимостей: `cli → agent, ui, project, llm, tools`; ядро (`agent`,
`llm`, `tools`, `project`) не импортирует `ui`/`rich` — это проверяет
`tests/test_layering.py`. Подробности и дорожная карта — в
[docs/ANALYSIS.md](docs/ANALYSIS.md).

### Формат function calling GigaChat

GigaChat использует **legacy-формат `functions`** (не `tools`):
запрос содержит массив `functions` и `function_call: "auto"`; в ответе приходит
`message.function_call` с `name` и **уже распарсенным объектом** `arguments`
(не строкой), плюс непрозрачный `functions_state_id`, который возвращается вместе
с ходом ассистента. Результат инструмента отправляется сообщением с
`role: "function"`. Всё это инкапсулировано в `llm/gigachat.py`.

## Установка

Требуется Python ≥ 3.10 и [uv](https://docs.astral.sh/uv/). Зависимости описаны в
`pyproject.toml`, точные версии зафиксированы в `uv.lock`.

```bash
uv sync                 # .venv + пакет + dev-группа (pytest, ruff)
uv run devassist        # запуск из окружения проекта

# установить CLI глобально, чтобы запускать devassist в любых проектах:
uv tool install --editable .
```

**Внутренний контур / зеркало PyPI.** Адрес зеркала в репозиторий не зашит —
задайте его переменной окружения, корпоративный CA — через системное хранилище:

```bash
export UV_DEFAULT_INDEX=https://<зеркало>/simple
export UV_SYSTEM_CERTS=1        # в старых версиях uv: UV_NATIVE_TLS=1
# или явно: export SSL_CERT_FILE=/path/to/ca-bundle.pem
```

Если uv недоступен, работает и обычный `pip install -e .` (без лок-файла).

## Конфигурация (учётные данные)

Секреты не хранятся в коде. Скопируйте пример и заполните **одну** из схем:

```bash
cp .env.example .env
# отредактируйте .env: либо GIGACHAT_ACCESS_KEY, либо GIGACHAT_CERT + GIGACHAT_KEY
```

### Две схемы авторизации

Схема выбирается **автоматически** по наличию реквизитов:

1. **OAuth по ключу (внешний контур / интернет).** Задан `GIGACHAT_ACCESS_KEY` —
   Basic-ключ обменивается на Bearer-токен (с авто-refresh). Эндпоинт по умолчанию
   — `https://gigachat.devices.sberbank.ru/api/v1`.
2. **mTLS по сертификату (внутренний контур).** Ключ не задан, но заданы
   `GIGACHAT_CERT` и `GIGACHAT_KEY` — клиент предъявляет сертификат на TLS-уровне,
   токен и заголовок `Authorization` не нужны. Эндпоинт по умолчанию —
   `https://gigachat-ift.sberdevices.delta.sbrf.ru/v1`.

Если задан `GIGACHAT_ACCESS_KEY`, используется схема OAuth (она в приоритете).
Явный `GIGACHAT_URL` всегда перекрывает URL по умолчанию.

Ключевые переменные (`.env` или окружение):

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `GIGACHAT_ACCESS_KEY` | Basic-ключ (base64 `client_id:client_secret`) — схема **OAuth** | — |
| `GIGACHAT_CERT` | путь к клиентскому сертификату (PEM) — схема **mTLS** | — |
| `GIGACHAT_KEY` | путь к приватному ключу — схема **mTLS** | — |
| `GIGACHAT_URL` | базовый URL API (перекрывает дефолт схемы) | по схеме |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` / `_B2B` / `_CORP` (только OAuth) | `GIGACHAT_API_PERS` |
| `GIGACHAT_MODEL` | модель | `GigaChat-3-Ultra` |
| `GIGACHAT_VERIFY_SSL` | проверка TLS-сертификата сервера | `0` (выкл.) |
| `GIGACHAT_TIMEOUT` | таймаут HTTP-запросов, с | `120` |
| `DEVASSIST_TEMPERATURE` | температура генерации (0–2) | `0.2` |
| `DEVASSIST_CONTEXT_TOKENS` | бюджет контекста (оценка в токенах); старая история сверх него отбрасывается | `60000` |
| `DEVASSIST_TEST_MODEL` | модель для live-тестов | `GigaChat-2-Max` |

Приоритет источников: аргументы CLI → переменные окружения → `.env` в корне
проекта → `.env` в текущей папке → значения по умолчанию. Значения из `.env`
**не** попадают в окружение процесса, а переменные `GIGACHAT_*` вычищаются из
окружения команд, которые запускает агент, — модель не может прочитать ключ
через `env`.

> Нужна **минимум одна** схема: либо `GIGACHAT_ACCESS_KEY`, либо пара
> `GIGACHAT_CERT` + `GIGACHAT_KEY`. Иначе клиент завершится с понятной ошибкой.

> **О моделях.** Приоритетная модель — `GigaChat-3-Ultra` (значение по умолчанию).
> Если она недоступна на вашем ключе, выберите доступную через `--model` или
> `GIGACHAT_MODEL`. Список доступных моделей: `devassist --list-models`.
> Live-тесты по умолчанию используют заведомо доступную `GigaChat-2-Max`.

## Использование

```bash
# интерактивный REPL (клавиши и статус-строка — см. «Интерфейс» ниже)
devassist
#   В REPL: /help, /model <имя>, /clear, /exit

# одноразовый запрос
devassist -p "найди все TODO в проекте и выведи список"

# выбор модели и каталога проекта
devassist -m GigaChat-2-Max -C ./my-project

# авто-подтверждение всех операций (осторожно!)
devassist -y -p "переименуй переменную foo в bar во всех .py файлах"

# отключить потоковый вывод (ответ целиком в конце)
devassist --no-stream -p "что делает этот проект?"

# список доступных моделей
devassist --list-models
```

Можно запускать и как модуль: `python -m devassist ...`.

Коды возврата одноразового режима: `0` — успех, `1` — ошибка конфигурации,
`2` — ошибка обращения к GigaChat, `130` — прервано (Ctrl+C).

### Интерфейс

- Ответ модели форматируется как Markdown прямо во время генерации: готовые блоки
  печатаются окончательно, ещё растущий блок перерисовывается внизу экрана.
- Пока модель думает или работает инструмент (например, долгий `pytest`), внизу
  крутится индикатор с прошедшим временем. Длинный вывод команд показывается
  сокращённо (начало и конец) — модель при этом получает его полностью.
- Под строкой ввода — статус: модель, заполнение контекста (жёлтый от 50%,
  красный от 80% бюджета `DEVASSIST_CONTEXT_TOKENS`), потрачено токенов за сессию,
  предупреждение о режиме `-y`. После каждого хода — итог: шаги, инструменты,
  время, токены.

| Клавиша | Действие |
|---|---|
| Enter | отправить |
| `\` + Enter, Alt+Enter | новая строка (вставка многострочного текста не отправляет его) |
| `/`, Tab | меню слеш-команд с описаниями |
| ↑ ↓, → | история ввода, принять подсказку из истории |
| Ctrl+C | на приглашении — сбросить ввод, во время ответа — прервать ход |
| Ctrl+D, `/exit` | выход |

Alt+Enter доходит не во всех терминалах (в Windows Terminal он переключает
полноэкранный режим, в macOS Terminal нужна опция «Use Option as Meta key») —
надёжный способ перенести строку — `\` в конце и Enter.

Если вывод перенаправлен (`devassist -p … > answer.md`) или ввод идёт не с
терминала, интерактивных элементов нет: ответ печатается как есть, сырым Markdown.

### Инструкции проекта

Если в корне проекта есть `DEVASSIST.md`, его содержимое добавляется в контекст
агента — удобно держать там соглашения проекта, команды сборки, заметки.
`DEVASSIST.local.md` — личные заметки (добавьте его в `.gitignore`).

### Служебная папка `.devassist/`

Рабочие данные агента хранятся в `.devassist/` в корне проекта: сейчас это
история ввода REPL (`history`), в будущем — индекс проекта и сохранённые чаты.
История содержит всё, что вы вводили, — включая случайно вставленные секреты. Папка создаётся автоматически при первой
записи и содержит собственный `.gitignore` со `*` — её содержимое не попадает
в репозиторий.

## Тестирование

Все тесты запускаются одной командой:

```bash
uv run pytest      # или: make test-all
```

- **Юнит-тесты инструментов** (без сети) — быстрые, выполняются всегда: на каждый
  инструмент (чтение/запись/редактирование/поиск/shell/git) и на песочницу.
- **Live-тесты LLM** (маркер `live`) — реально обращаются к GigaChat и проверяют
  все типы вызовов: простой запрос-ответ, одиночный tool call, многошаговый диалог
  с возвратом результата инструмента в модель.
- **Сквозной smoke-тест** — гоняет агент на настоящей мини-задаче (создать файл →
  отредактировать → выполнить команду) от начала до конца.

Live-тесты автоматически **пропускаются**, если реквизиты GigaChat не заданы
(ключ или пара cert+key в окружении либо в `.env` репозитория). Запуск только
офлайн- или только live-тестов:

```bash
uv run pytest -m "not live"   # быстрые офлайн-тесты (make test)
uv run pytest -m live         # только живые (нужен ключ; медленнее)
```

## Модель безопасности

- **Песочница**: любые файловые операции ограничены корнем проекта; выход за его
  пределы (`../`, абсолютные пути, симлинки) отклоняется.
- **Подтверждения**: изменяющие операции (`write_file`, `edit_file`, `run_shell`,
  пишущий `git`) требуют подтверждения; опасные shell-команды (`rm -rf`, `sudo`,
  `git reset --hard`, сетевые загрузки и т.п.) помечаются отдельно. Флаг `-y`
  отключает запросы — используйте осознанно. Операция, которую невозможно
  выполнить (путь вне проекта, запрещённая подкоманда), отклоняется до запроса
  подтверждения.
- **Процессы**: команды запускаются без доступа к терминалу (stdin пуст), в
  отдельной группе процессов, которая целиком останавливается по таймауту
  (1–600 с), по Ctrl+C и если фоновые потомки (`cmd &`) продолжают работать после
  выхода команды. Из окружения удаляются `GIGACHAT_*`.
- **Git**: опции `--output`, `--no-index`, `--ext-diff`, `--pathspec-from-file`
  запрещены (запись/чтение вне проекта); `branch` без подтверждения — только
  просмотр веток; редактор не открывается (для `commit` нужен `-m`).
- **Поиск**: `search_content` не читает `.env*` (кроме `.env.example`), бинарные
  файлы и файлы больше 1 МБ; `find_files` не принимает шаблоны с `..` и
  абсолютные пути.
```
