# Анализ кодовой базы devassist и план реорганизации

Документ фиксирует состояние кода версии 0.1.0, найденные проблемы и целевую
архитектуру, подготовленную под следующие улучшения:

1. Нормальный CLI-интерфейс с поддержкой форматирования.
2. Принудительная остановка при зацикливании агента на вызове инструментов.
3. Индекс проекта для работы с большими кодовыми базами (в `.devassist/`).
4. Сохранение чатов по умолчанию в `.devassist/chats/`.
5. Автоматическое сжатие контекста (по лимиту и по команде).
6. Поддержка `AGENTS.md`.

В рамках этой реорганизации фичи **не реализуются** — создаются точки расширения,
исправляются баги и уязвимости, код разводится по слоям.

## 1. Исходная архитектура (0.1.0)

```
cli.py ──► Agent (agent/loop.py) ──► LLMProvider (llm/gigachat.py)
   │          │  ├─► Session (agent/session.py) ──► context.py (обход ФС)
   │          │  ├─► ToolRegistry (tools/*) ──► security.py
   │          └──┴─► Console (ui/console.py, rich)  ← прямые вызовы из ядра
   └─► Config (config.py, читает .env в os.environ)
```

Сильные стороны, которые сохраняются: провайдер скрыт за `LLMProvider`; инструменты
единообразны (pydantic → JSON-schema под GigaChat); песочница путей; устойчивый к
ошибкам модели `edit_file`; хорошие офлайн-тесты инструментов.

## 2. Найденные проблемы

Серьёзность: **H** — падение, утечка секретов или выход из песочницы;
**M** — неверное поведение/зависание; **L** — шероховатости.

```

  security.py          песочница путей + классификация shell-команд
  project/             знание о проекте (без LLM и UI)
    workspace.py       Workspace: корень, .devassist/ (лениво, с .gitignore "*"), chats_dir, index_dir

    symbols.py         извлечение определений: ast для Python, регэкспы       (фича 3)
    index.py           ProjectIndex: SQLite в .devassist/index, инкрементальный (фича 3)
    instructions.py    файлы инструкций (AGENTS.md, GIGACODE.md, DEVASSIST*.md) корня и подкаталогов (фича 6)

  tools/               Tool (describe, Display), реестр, process.py (безопасный запуск процессов)
  agent/               ядро без UI
    events.py          AgentEvents — протокол событий для UI (no-op база, confirm → False)
    conversation.py    история диалога: сериализация, repair, last_usage, краткое содержание (Summary)
    compaction.py      сжатие контекста: план, транскрипт, итеративное резюме     (фича 5)
    chat_store.py      сохранённые чаты: ChatStore (.devassist/chats), ChatRecorder
    context_window.py  оценка токенов и окно истории под бюджет
    guard.py           LoopGuard: лимит шагов, серия ошибок, повторы вызовов; бюджет и похожие вызовы суб-агента
```

Направление зависимостей: `cli → agent, ui, project, llm, tools`; `ui → agent.events,
tools.base`; `agent → llm, tools, project`; `tools → project, security, errors`.
Ядро (`agent/*`) не импортирует `ui` и `rich` — это проверяется тестом.

## 6. Реализация фич

### Фича 1. CLI-интерфейс (выполнено)

- **Живой Markdown** — `ui/markdown_stream.py`: ответ делится на завершённые блоки
  верхнего уровня (границы — парсером rich) и растущий хвост. Завершённое печатается
  один раз перерендером префикса, поэтому поток печатает ровно то же, что рендер
  целиком (свойство проверяется тестом на посимвольной и случайной нарезке). Хвост
  рисуется во временной области `Live`.
- **Временная область** — одна на консоль (`ui/console.py`, `_LiveArea`): индикаторы
  «думаю / печатает / выполняется» с временем и хвост ответа. Анимацию двигает свой
  поток под общей с печатью блокировкой: встроенное авто-обновление rich рисует
  область параллельно с печатью над ней и при гонке стирает напечатанные строки.
  В не-терминале области нет — текст печатается как есть.
- **Ядро** — новые события `on_tool_start/on_tool_end` (вокруг `tool.run`, конец —
  в `finally`); ожидание ответа сигнализируется и в `--no-stream`;
  `TurnStats.duration_s`; `Agent.context_tokens`, `Agent.billed_tokens` (точен и при
  прерванном ходе), `Agent.config`.
- **Строка ввода** — `cli/prompt.py`: автодополнение из `CommandRegistry`, история
  в `.devassist/history` (папка создаётся при первом вводе, ошибки записи не роняют
  REPL), многострочный ввод, статус-строка из `StatusInfo`.
- **Esc** — `cli/interrupt.py`: на время хода терминал в cbreak-режиме, фоновый поток
  читает клавиши; одиночный Esc (не начало ESC-последовательности) доставляет
  SIGINT основному потоку (`pthread_kill`), поэтому прерывание идёт тем же путём,
  что Ctrl+C, включая убийство группы процессов команды. Набранный текст копится и
  подставляется в следующий ввод; перед вопросом о подтверждении чтение
  приостанавливается (`Console.set_interrupt_keys`). Esc Esc на приглашении — очистка
  ввода с сохранением черновика в истории.
- **Вопросы пользователю** — инструмент `tools/ask_user.py` (SAFE, без
  подтверждения) зовёт `ToolContext.ask_user` → `AgentEvents.ask_user`; типы — в
  `tools/questions.py` (ядро не знает о UI). UI — `ui/choice.py`: встроенное меню
  prompt_toolkit, свой ответ печатается прямо в меню (одно приложение — без потери
  клавиш между приложениями). На время вопросов Esc-перехват хода приостанавливается.
  Отказ отвечать — не ошибка инструмента (не приближает стоп по серии ошибок).
  Не проверено вживую: принимает ли GigaChat вложенные массивы объектов в схеме
  функций (`uv run pytest -m live` с реквизитами).
- Известное ограничение: ссылки-сноски, определённые ниже места использования, в уже
  напечатанной части ответа остаются текстом.

### Фича 2. Остановка при зацикливании (выполнено)

- **Ключ вызова** — `guard.call_key`: имя инструмента + JSON аргументов с
  упорядоченными ключами (`sort_keys`), порядок полей в ответе модели не важен.
- **Повтор** — тот же ключ, причём между вызовами не было успешной изменяющей
  операции (риск ≥ WRITE) *другого* вызова. Собственное изменение повтор не
  сбрасывает: `run_shell pytest` ×N без правок — зацикливание, правка → `pytest` —
  нет. Счёт ведётся по ключу, поэтому чередование read-only вызовов A, B, A, B тоже
  ловится. Неудачный вызов изменением не считается.
- **Пороги** — `Config.max_tool_repeats = 3`. `LoopGuard.before_tool` перед
  выполнением возвращает `CallCheck`: на 3-м повторе вызов выполняется, а к его
  результату для модели дописывается предупреждение (пользователь видит
  `on_notice(level="warn")`); 4-й не выполняется — висящий `function_call`
  закрывается заметкой через `Conversation.repair`, ход останавливается
  (`StopReason.kind == "tool_repeats"`).
- **Отказ пользователя** — `ToolOutcome(rejected=True)`: не продолжает и не
  сбрасывает серию ошибок. Ключ запоминается до конца хода: повтор того же вызова
  отклоняется без вопроса (модели — отдельная заметка) и учитывается детектором.
  В следующем ходе пользователя спрашивают снова.
- Известные ограничения: аргументы не нормализуются (`./a.py` и `a.py` — разные
  вызовы); чередование разных изменяющих команд (`run_shell A`, `run_shell B`, …)
  повтором не считается — его ограничивает `max_steps`.

### Фича 3. Индекс проекта (выполнено)

- **`.gitignore`** — `project/gitignore.py`: правило → regex (тот же glob-компилятор,
  что у `glob_match`), `IgnoreStack` — правила по каталогам сверху вниз, решает
  последнее совпадение. `walk_files` отсекает исключённые каталоги до спуска и
  применяет правила каталогов выше `base`; то же решение для одного пути —
  `is_excluded`. Действует на `find_files`, `search_content`, дерево в промпте и индекс.
- **Символы** — `project/symbols.py`: чистые функции без SQLite. Python — `ast`
  (классы, функции, методы, константы модуля, определения под `if`/`try`; вложенные
  функции — шум, не индексируются), при `SyntaxError` — регэкспы; Markdown —
  заголовки с иерархией; остальные языки — построчные регэкспы (диапазон строк
  неизвестен, вложенность — только у методов Go).
- **Индекс** — `project/index.py`, SQLite в `.devassist/index/index.sqlite3`
  (stdlib, без загрузки в память; WAL). Таблицы `files` (размер, `mtime_ns`, язык,
  строки, статус: indexed/large/binary/error) и `symbols`. Обновление сравнивает
  `(size, mtime_ns)`; фиксация пачками по 200 файлов, поэтому прерывание теряет
  только текущую пачку. `meta.complete` выставляется в конце полного обхода —
  по нему CLI решает, строить ли индекс при запуске. Несовместимая версия схемы или
  повреждённая база пересоздаются. Поиск: `LIKE` по `name_lower` с ранжированием
  точное > префикс > вхождение, `Класс.метод`, обобщённые виды (`function` включает
  методы), glob-фильтр.
- **Инструменты** — `tools/index.py`: `find_symbol`, `file_outline` (SAFE). Индекс
  открывается из `ToolContext.workspace` и обновляется перед запросом (оглавление —
  только своего файла/каталога), поэтому ядро (`agent/loop.py`) и `ToolContext` не
  менялись. Ошибки SQLite/ФС → `ToolError`.
- **CLI** — `cli/indexing.py`: `ensure_index` после баннера REPL, до первого ввода;
  построение — внутри того же `EscInterrupt`, что и ход агента (Esc → SIGINT →
  `KeyboardInterrupt`), индикатор — `Console.progress`; набранное во время
  построения подставляется в строку ввода. Ошибка индекса не мешает работе REPL.
  `/index [rebuild]`. Одноразовый режим индекс заранее не строит (база
  создаётся, только когда агент обратится к индексу).
- **Безопасность** — `write_file`/`edit_file` не пишут в `.devassist/` (п. 2.3).
- Ограничения: `.gitignore` выше корня проекта и глобальный `core.excludesFile` не
  читаются; индекс знает определения, но не использования (для них —
  `search_content`); полный обход файлов перед каждым `find_symbol` на очень больших
  репозиториях стоит заметного времени (статы без чтения содержимого); первичное
  построение — порядка 1 000 файлов/с на типичном Python-коде.

### Фича 4. Сохранение чатов (выполнено)

- **Хранилище** — `agent/chat_store.py` (ядро, без UI). Файл на чат:
  `.devassist/chats/<id>.json` = метаданные (`title` — первый запрос, `created_at`,
  `updated_at`, `model`, `requests`, `preview` — начало последнего ответа) +
  `Conversation.to_dict()`; у обёртки своя `version`. Id `YYYYMMDD-HHMMSS-<8 hex>`:
  сортируется по времени; если при первой записи нового чата файл с таким id уже
  есть (другое окно в ту же секунду), id выбирается заново. Запись атомарная
  (`mkstemp` в том же каталоге → `os.replace`), права 0600. `recent()` отбирает
  файлы по mtime и разбирает только верх списка, битые файлы и чужие версии
  пропускает; `find()` — по id или однозначному префиксу; `load()` делает `repair()`.
- **Текущий чат** — `ChatRecorder`: куда писать (`chat_id`, `created_at`),
  `start_new()` для `/clear`, `switch_to()` для продолжения. Пустой диалог не
  пишется; `OSError` отключает сохранение до конца сессии с одним предупреждением
  (как история ввода).
- **Когда сохраняется** — в CLI после каждого хода (`cli/repl.autosave`), в том
  числе прерванного и упавшего: `run_turn` к этому моменту уже вызвал `repair()`.
  Сохранение не привязано к `on_turn_end`, который при прерывании не приходит.
  Одноразовый режим тоже сохраняет — на этом работает `devassist -c -p …`.
- **Продолжение** — `Agent.reset(conversation)`: системный промпт собирается
  заново по текущему проекту, модель — текущая, `context_tokens` — из `last_usage`
  сохранённого диалога. `/resume [id]` (алиас `/chats`), флаги `-c`/`--continue`,
  `-r`/`--resume [ID]` (без ID — селектор, отмена → новый чат), `--no-save` /
  `DEVASSIST_SAVE_CHATS=0`.
- **Селектор** — `ui/chat_picker.py`, встроенное приложение prompt_toolkit по
  образцу `ui/choice.py`: окно из 8 чатов с прокруткой, ↑↓ по кругу, PgUp/PgDn и
  Home/End без перехода через край, поиск по заголовку/ответу/id (все слова, без
  учёта регистра), у выбранного — preview, id, модель; текущий чат помечен. Без
  терминала — таблица и ввод номера (`Console.pick_chat`). После выбора
  `Console.chat_resumed` печатает последний запрос и ответ.
- **Безопасность** — запрет записи в `.devassist/` общий с фичей 3
  (`tools/fs._writable_path`); добавлена проверка без учёта регистра
  (`Workspace.is_data_path`: на macOS/Windows `.DEVASSIST` — та же папка).
- Известные ограничения: один чат, продолженный в двух окнах одновременно, —
  «последний записавший побеждает»; старые чаты не удаляются автоматически;
  `recent()` читает файлы целиком (для сотен чатов достаточно — при росте можно
  завести отдельный индекс метаданных).

### Режимы разрешений (выполнено)

- **Правила** — `permissions.decide(mode, risk, kind, auto_approve)` — единственное
  место, где сводятся режим, риск вызова, вид инструмента (`Tool.kind`:
  `EDIT` — `write_file`/`edit_file`, `COMMAND` — `run_shell`, `OTHER` — остальное) и
  `-y`. Результат — `ALLOW`/`ASK`/`BLOCK`; агентный цикл только исполняет решение.
  Режим плана запрещает правки и изменяющий `git` даже с `-y`; `run_shell` в плане
  подтверждается (для тестов и просмотра). Заблокированный вызов — обычная ошибка
  инструмента: серия таких попыток останавливает ход.
- **Состояние** — режим живёт в `Agent` (`mode`/`set_mode`/`cycle_mode`), как модель;
  `Config.mode` — начальный (`--mode`, `DEVASSIST_MODE`). Читается при каждом вызове
  инструмента и каждом запросе, поэтому смена посреди хода действует со следующего
  вызова. Правила режима плана дописываются к системному сообщению в
  `_build_request` (`prompts.mode_prompt`), кэшируемый системный промпт не меняется.
- **Выход из плана** — инструмент `tools/plan.py` (`exit_plan_mode`) получает режим
  через `ToolContext.get_mode/set_mode` и спрашивает пользователя тем же
  `ToolContext.ask_user`; план — `Question.body`, UI печатает его Markdown-панелью
  над меню. Одобрение меняет режим и возвращает модели «приступай» — выполнение
  продолжается в том же ходе.
- **Клавиши** — Shift+Tab на приглашении: привязка `s-tab` в `cli/prompt.py` с
  фильтром `~has_completions` (в меню дополнения остаётся «назад»). Во время хода:
  `KeyParser` распознаёт `ESC [ Z` без параметров и зовёт `EscInterrupt.on_backtab`
  из фонового потока (запись атрибута агента); индикатор хода перечитывает режим
  при каждой отрисовке (`Console.set_mode_hint`), печати из фонового потока нет.
  На время вопросов (подтверждение, меню) чтение клавиш приостановлено — Shift+Tab
  там не работает.

### Фича 5. Сжатие контекста (выполнено)

- **Модель данных** — журнал диалога не переписывается: `Summary(text, upto)` в
  `Conversation` заменяет `messages[:upto]` только в том, что видит модель
  (`context_messages()`). Если после границы нет запроса пользователя (сжатие посреди
  хода), спереди добавляется последний запрос — закрепление вычисляется, а не
  хранится, и исчезает с новым запросом. Граница не может приходиться на результат
  инструмента; `set_summary` сбрасывает `last_usage`. В файле чата — необязательный
  ключ `summary`, версия формата прежняя: старая версия devassist просто отправит
  журнал целиком.
- **Сжатие** — `agent/compaction.py` без UI: `plan_compaction` идёт по блокам
  «сообщение + результаты его вызова» с конца и оставляет свежие в пределах
  `keep_tokens`; вход суммаризатора — часть вида до новой границы (с закреплённым
  запросом). Транскрипт — плоский текст (результаты ~2000 символов с вырезом
  середины); куски по оценке токенов, на вход — три последних и всегда последний
  запрос пользователя (как в `fit_history`); резюме обновляется
  итеративно запросом без инструментов. `finish_reason != "stop"`, пустой ответ или
  резюме не короче истории → `CompactionError(LLMError)`.
- **Агент** — краткое содержание дописывается к единственному системному сообщению
  в `_build_request` (`summary_prompt` помечает его как сведения, а не указания).
  Порог и объёмы — доли **бюджета истории** (бюджет запроса минус системное
  сообщение и схемы): на окне 8K накладные ~3.5K съели бы долю от всего бюджета, и
  сжатие запускалось бы на каждом шаге. Автозапуск — перед обращением к модели,
  когда история ≥ `compact_threshold` (80%); остаётся ~25% свежего, сжатие
  пропускается, если сворачивать < 20% (защита от повторов). Ошибка —
  `on_notice(warn)` и отказ от попыток до конца хода; страховкой остаётся
  `fit_history`. Диалог меняется только после успешного ответа, поэтому прерывание
  его не портит. Токены суммаризации — в `billed_tokens` и `TurnStats`, в том числе
  уже оплаченные куски при сбое. `context_tokens` после сжатия — оценка, посчитанная
  один раз, до первого ответа модели.
- **UI/CLI** — `on_compact_start/on_compact_end(CompactResult | None)`, индикатор во
  временной области; `/compact [пожелания]` под Esc-прерыванием, после успеха чат
  сохраняется; `DEVASSIST_AUTO_COMPACT`, `DEVASSIST_COMPACT_THRESHOLD`. В тестах
  `ScriptedProvider` отправляет запросы без инструментов в отдельную очередь `summaries`.
- Известные ограничения: оценка токенов грубая (~3 символа на токен), поэтому
  порог срабатывает с запасом; Esc во время автосжатия прерывает весь ход; более
  ранняя, чем три куска, часть очень длинной несжатой истории в резюме не попадает
  (модель её и так уже не видела) — кроме последнего запроса пользователя.

### Фича 6. AGENTS.md (выполнено)

- **Имена и приоритет** — `INSTRUCTION_FILES = (AGENTS.md, GIGACODE.md, DEVASSIST.md,
  DEVASSIST.local.md)`: порядок — возрастание приоритета (общий формат агентов →
  GigaCode → devassist → личное). Правило приоритетов в `SYSTEM_PROMPT`: позже в
  списке важнее, подкаталог важнее корня, указания пользователя важнее файлов.
- **Чтение** — `load_instructions(..., directory=)`: имя — путь от корня; повтор
  одного файла под разными именами (симлинк) пропускается; лимит 20 000 символов на
  файл и 30 000 на каталог — место сначала получают приоритетные, файл без места
  попадает в промпт ссылкой «прочитай read_file».
- **Подкаталоги** — `NestedInstructions`: `Tool.paths(params)` (по умолчанию поле
  `path`) после успешного вызова → каталоги от корня (не включая) до каталога пути,
  каждый проверяется один раз; `is_excluded` — для каталогов (`node_modules`,
  `.devassist`, `.gitignore`), а не для файлов (`DEVASSIST.local.md` обычно в
  `.gitignore`). Найденное — производное состояние агента: рендерится в системном
  сообщении (`nested_instructions_prompt`, общий лимит 20 000 символов), поэтому
  переживает обрезку и сжатие без дублей. Пользователь видит `on_notice`.
  `reset()` (`/clear`, `/resume`) очищает накопитель.
- Известные ограничения: инструкции подкаталога появляются только после первого
  успешного обращения к его путям (`find_files`, `find_symbol`, `run_shell` путей не
  называют); при продолжении чата подключаются заново при первом обращении;
  смена системного сообщения при новой находке сбрасывает кеш промпта GigaChat.

### Фича 7. Суб-агенты (выполнено)

- **Шов** — `ToolContext.run_subagent` (колбэк от агента, как `ask_user`): инструмент
  `tools/task.py` (`task`) не импортирует ядро, а описания встроенных агентов
  (`SubagentSpec`: `explore` — только чтение, `general` — все инструменты, кроме
  `SUBAGENT_EXCLUDED`) — данные, общие для инструмента и ядра.
- **Суб-агент — обычный `Agent`** с `parent=`/`subagent=`: своя история, урезанный
  реестр (`ToolRegistry.subset`), свой системный промпт (`SUBAGENT_PROMPT` + промпт
  агента + контекст проекта основного агента), лимит шагов
  `subagent_max_steps`. Общие с основным: режим (делегирование `mode`/`set_mode`),
  разрешения «всегда», калибровка токенов, инструкции подкаталогов; расход токенов
  (`_bill` → `_bill_child`) — в сессию и в статистику идущего хода основного.
- **События** — прокси `SubagentEvents`: поток и текст суб-агента глушатся, шаги —
  хуками `on_subagent_*`, подтверждения — обычным `confirm`. Отчёт
  (`subagent_report`) — текст модели (≤ 8 000 символов) + факты, собранные
  прокси: изменённые файлы, команды, отклонённое.
- **Остановка** — флаг до прерывания: `EscInterrupt.on_escape` →
  `Agent.request_subagent_stop()` (уровень 1 — итог, 2 — обрыв), затем обычный
  `KeyboardInterrupt`. Суб-агент на уровне 1 подводит итог (`_user_stop`), на 2 —
  `_run_subagent` возвращает «оборван»; без флага (Ctrl+C) — ход останавливается.
- **Ограничители** — `LoopGuard(max_tokens, time_limit, max_similar)` и
  `pressure()`; у основного агента выключены. `ToolResult.changed` передаёт
  ограничителю основного агента, что суб-агент менял проект.

## 7. Анализ 0.5.x: логические ошибки и UX (выполнено)

Второй проход по всем модулям после фич 1–6 и режимов разрешений. Находки
воспроизводились на исходном коде (каждая правка — с регрессионным тестом, который
