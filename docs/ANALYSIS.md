# Анализ кодовой базы devassist и план реорганизации

Документ фиксирует состояние кода версии 0.1.0, найденные проблемы и целевую
архитектуру, подготовленную под следующие улучшения:

1. Нормальный CLI-интерфейс с поддержкой форматирования.
2. Принудительная остановка при зацикливании агента на вызове инструментов.
3. Индекс проекта для работы с большими кодовыми базами (в `.devassist/`).
4. Сохранение чатов по умолчанию в `.devassist/chats/`.
5. Автоматическое сжатие контекста (по лимиту и по команде).
6. Поддержка `AGENTS.md`.

В рамках этой реорганизации фичи **не реализуются** — создаются точки расширения,
исправляются баги и уязвимости, код разводится по слоям.

## 1. Исходная архитектура (0.1.0)

```
cli.py ──► Agent (agent/loop.py) ──► LLMProvider (llm/gigachat.py)
   │          │  ├─► Session (agent/session.py) ──► context.py (обход ФС)
   │          │  ├─► ToolRegistry (tools/*) ──► security.py
   │          └──┴─► Console (ui/console.py, rich)  ← прямые вызовы из ядра
   └─► Config (config.py, читает .env в os.environ)
```

Сильные стороны, которые сохраняются: провайдер скрыт за `LLMProvider`; инструменты
единообразны (pydantic → JSON-schema под GigaChat); песочница путей; устойчивый к
ошибкам модели `edit_file`; хорошие офлайн-тесты инструментов.

## 2. Найденные проблемы

Серьёзность: **H** — падение, утечка секретов или выход из песочницы;
**M** — неверное поведение/зависание; **L** — шероховатости.

### 2.3. Зафиксировано, но не меняется в этом шаге

Это продуктовые решения, требующие обсуждения:

- `GIGACHAT_VERIFY_SSL=0` по умолчанию: Basic-ключ уязвим для MITM. Долгосрочно —
  поддержка `GIGACHAT_CA_BUNDLE` (корневой сертификат Минцифры) и включение проверки.
- Флаг `-y` авто-подтверждает и DANGEROUS-команды (`rm -rf`, `git reset --hard`).
- Отказ пользователя считается «неудачным вызовом» и приближает остановку по серии
  ошибок — решить вместе с детектором зацикливания (п.2).
- `.devassist/` доступна на запись `write_file`/`edit_file` — закрыть, когда там
  появятся индекс и чаты (п.3–4).
- `read_file .env` разрешён (поиск `.env` теперь пропускает, явное чтение — нет).
- Проверка классификатором shell-команд — эвристика (regex); все команды и так
  требуют подтверждения, но классификация не является защитой.

## 3. Целевая архитектура

```
devassist/
  errors.py            ToolError, SandboxError(ToolError)
  config.py            неизменяемый Config; .env читается без мутации os.environ
  security.py          песочница путей + классификация shell-команд
  project/             знание о проекте (без LLM и UI)
    workspace.py       Workspace: корень, .devassist/ (лениво, с .gitignore "*"), chats_dir, index_dir
    files.py           единые правила игнорирования, обходчик с прунингом, glob-матчер, дерево
    instructions.py    файлы инструкций проекта (DEVASSIST.md, DEVASSIST.local.md → +AGENTS.md)
  llm/                 LLMProvider/LLMError, Usage, GigaChat (model= на вызов, транспорт для тестов)
  tools/               Tool (describe, Display), реестр, process.py (безопасный запуск процессов)
  agent/               ядро без UI
    events.py          AgentEvents — протокол событий для UI (no-op база, confirm → False)
    conversation.py    история диалога: сериализация, repair, last_usage
    context_window.py  оценка токенов и окно истории под бюджет
    guard.py           LoopGuard: лимит шагов, серия ошибок (+ повторы в п.2)
    prompts.py         сборка системного промпта
    loop.py            Agent: оркестрация, reset/set_model, единая точка _build_request
  ui/                  theme.py (палитра), console.py (rich-реализация AgentEvents)
  cli/                 app.py (композиция, argparse), repl.py, commands.py (реестр /команд)
```

Направление зависимостей: `cli → agent, ui, project, llm, tools`; `ui → agent.events,
tools.base`; `agent → llm, tools, project`; `tools → project, security, errors`.
Ядро (`agent/*`) не импортирует `ui` и `rich` — это проверяется тестом.

## 6. Реализация фич

### Фича 1. CLI-интерфейс (выполнено)

- **Живой Markdown** — `ui/markdown_stream.py`: ответ делится на завершённые блоки
  верхнего уровня (границы — парсером rich) и растущий хвост. Завершённое печатается
  один раз перерендером префикса, поэтому поток печатает ровно то же, что рендер
  целиком (свойство проверяется тестом на посимвольной и случайной нарезке). Хвост
  рисуется во временной области `Live`.
- **Временная область** — одна на консоль (`ui/console.py`, `_LiveArea`): индикаторы
  «думаю / печатает / выполняется» с временем и хвост ответа. Анимацию двигает свой
  поток под общей с печатью блокировкой: встроенное авто-обновление rich рисует
  область параллельно с печатью над ней и при гонке стирает напечатанные строки.
  В не-терминале области нет — текст печатается как есть.
- **Ядро** — новые события `on_tool_start/on_tool_end` (вокруг `tool.run`, конец —
  в `finally`); ожидание ответа сигнализируется и в `--no-stream`;
  `TurnStats.duration_s`; `Agent.context_tokens`, `Agent.billed_tokens` (точен и при
  прерванном ходе), `Agent.config`.
- **Строка ввода** — `cli/prompt.py`: автодополнение из `CommandRegistry`, история
  в `.devassist/history` (папка создаётся при первом вводе, ошибки записи не роняют
  REPL), многострочный ввод, статус-строка из `StatusInfo`.
- **Esc** — `cli/interrupt.py`: на время хода терминал в cbreak-режиме, фоновый поток
  читает клавиши; одиночный Esc (не начало ESC-последовательности) доставляет
  SIGINT основному потоку (`pthread_kill`), поэтому прерывание идёт тем же путём,
  что Ctrl+C, включая убийство группы процессов команды. Набранный текст копится и
  подставляется в следующий ввод; перед вопросом о подтверждении чтение
  приостанавливается (`Console.set_interrupt_keys`). Esc Esc на приглашении — очистка
  ввода с сохранением черновика в истории.
- **Вопросы пользователю** — инструмент `tools/ask_user.py` (SAFE, без
  подтверждения) зовёт `ToolContext.ask_user` → `AgentEvents.ask_user`; типы — в
  `tools/questions.py` (ядро не знает о UI). UI — `ui/choice.py`: встроенное меню
  prompt_toolkit, свой ответ печатается прямо в меню (одно приложение — без потери
  клавиш между приложениями). На время вопросов Esc-перехват хода приостанавливается.
  Отказ отвечать — не ошибка инструмента (не приближает стоп по серии ошибок).
  Не проверено вживую: принимает ли GigaChat вложенные массивы объектов в схеме
  функций (`uv run pytest -m live` с реквизитами).
- Известное ограничение: ссылки-сноски, определённые ниже места использования, в уже
  напечатанной части ответа остаются текстом.
