# Changelog

Все значимые изменения проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект придерживается [семантического версионирования](https://semver.org/lang/ru/).

## [Unreleased]

### Security
- `write_file`/`edit_file` не пишут во внутренности git (`.git/` на любой глубине и
  в любом регистре, каталог из `gitdir:`): правка `.git/config` (`core.fsmonitor`,
  `diff.external`) превращала `git status`/`git diff`, которые выполняются без
  подтверждения, в запуск произвольной команды — в режиме авто-правок без единого
  вопроса. git запускается с `core.fsmonitor=false`, `safe.bareRepository=explicit`,
  а `diff`/`log`/`show` — с `--no-ext-diff`.
- `-y` больше не выполняет опасные команды без вопроса (`rm -rf`, `sudo`,
  `git reset --hard`, принудительный `git push`…); прежнее поведение — `--yes-all`.
- `GIGACHAT_CA_BUNDLE` — корневой сертификат для проверки TLS (включает её); при
  OAuth без проверки REPL предупреждает.
- `.devassist/history` создаётся с правами 0600.

### Fixed
- Правка CRLF-файла переписывала весь файл в LF (на Windows — LF в CRLF); теперь
  сохраняются переводы строк и BOM файла.
- Прерывание или нехватка места посреди записи оставляли файл пустым — запись
  атомарная.
- `edit_file` с пустым `old_string` и `replace_all` вставлял текст между всеми
  символами; несторогое совпадение ломало отступы (Python-файлы) и добавляло
  пустые строки.
- Дифф склеивал строки без перевода строки в конце (`-a+b`) и резал по `\x0c`.
- Перезапись бинарного или cp1251-файла выглядела в превью как создание нового —
  теперь отказ; `read_file` читает cp1251 и сообщает «строки a–b из N».
- Дерево проекта в системном промпте теряло файлы корня у проектов с крупным
  первым каталогом.
- Краткое содержание при сжатии обрезалось с конца — терялся следующий шаг.
- Голые JSON-значения в результатах инструментов (`42`, `[]`) уходили в GigaChat
  без обёртки; 502/503 при замере окна занижали окно навсегда; mTLS с
  `GIGACHAT_VERIFY_SSL=1` не мог проверить сервер (не было корневых сертификатов).
- Esc в самом конце хода мог оставить поток чтения клавиш и терминал без эха.
- `search_content`: ложное «достигнут лимит», номера строк расходились с
  `read_file`; `.env`: inline-комментарии и кавычки.

### Changed
- Минимальная версия Python — 3.13 (на 3.10–3.12 пакет больше не ставится).
- Замер окна незамеренной модели — с согласия (в REPL — вопрос, с `-y` — без
  вопроса; в `-p` и без терминала — только подсказка); `DEVASSIST_AUTO_MEASURE=0`.
- `-p`: код возврата 3, если ход остановлен ограничителем; прочие ошибки — код 1
  без traceback.
- Индекс при старте REPL строится только в git-репозитории.
- При остановке ограничителем модель кратко подводит итог.
- Ненулевой код выхода команды не приближает остановку «агент застрял».
- Оценка токенов калибруется по фактическому usage — сжатие не срабатывает
  раньше времени.
- Подтверждение: «a» — да и больше не спрашивать до конца сессии; глагол по виду
  операции, git — с кавычками.
- Потоковый Markdown не перерисовывает весь ответ на каждом блоке.

### Added
- Индекс проекта знает использования и импорты Python-кода (схема индекса v2 —
  старый индекс перестраивается автоматически). Новый инструмент
  `find_references`: вызовы, обращения к атрибутам, упоминания и строки импорта с
  объемлющей функцией или классом; ранжирование — файлы, импортирующие модуль
  определения (с учётом `import … as …`), затем файл определения, затем совпадения
  только по имени. `file_outline` для Python-файла показывает, что он импортирует из
  проекта и где импортируется сам; `find_symbol` и `file_outline` — первую строку
  докстринга; `/index` — число использований.
- Режимы разрешений (`devassist/permissions.py`): **ручной** (`manual`, как раньше —
  всё изменяющее с подтверждением), **авто-правки** (`edits` — `write_file`/`edit_file`
  без вопросов, команды и изменяющий `git` с подтверждением) и **план** (`plan` —
  только исследование: правки и изменяющий `git` заблокированы, `run_shell` с
  подтверждением, правила режима дописываются к системному промпту).
  - Shift+Tab переключает режим по кругу — на приглашении и во время хода (действует
    со следующего вызова инструмента); режим виден в статус-строке, индикаторе хода
    и баннере.
  - `/mode [manual|edits|plan]` с автодополнением, `--mode` при запуске,
    переменная `DEVASSIST_MODE`.
  - Инструмент `exit_plan_mode`: в режиме плана агент передаёт готовый план на
    одобрение — план показывается в рамке, затем меню «Да, правки без вопросов» /
    «Да, с подтверждением» / свой ответ (замечания). После одобрения режим меняется
    и агент продолжает в том же ходе.
  - `Tool.kind` (`ToolKind.EDIT`/`COMMAND`/`OTHER`), `ToolContext.get_mode`/`set_mode`,
    `Question.body` (Markdown над вариантами ответа), `Agent.mode`/`set_mode`/
    `cycle_mode`, `Config.mode`.
- Сжатие контекста (фича 5 дорожной карты): когда история занимает 80% бюджета
  истории, её начало сворачивается моделью в краткое содержание, которое уходит в
  системном сообщении вместо старых сообщений; свежие ~25% и текущий запрос остаются
  дословно, вызов и его результат не разделяются.
  - `/compact [пожелания]` — сжать весь диалог вручную (Esc — отменить).
  - `DEVASSIST_AUTO_COMPACT` (`0` — только вручную), `DEVASSIST_COMPACT_THRESHOLD`
    (порог в процентах, 10–95).
  - Повторное сжатие обновляет прежнее краткое содержание; длинная история
    пересказывается по кускам. Ошибка сжатия — предупреждение, дальше история
    укладывается в бюджет скользящим окном, как раньше.
  - Индикатор «сжимаю историю» и итог «✂ контекст сжат: ~X → ~Y ток.»; токены
    суммаризации входят в потраченные.
  - Журнал чата не переписывается: краткое содержание хранится рядом (необязательный
    ключ `summary` в файле чата, формат прежний) и восстанавливается при продолжении.
  - `agent/compaction.py`, `Conversation.summary`/`set_summary`/`context_messages`,
    `Agent.compact`, события `on_compact_start`/`on_compact_end` (`CompactResult`),
    `Config.auto_compact`/`compact_threshold`.
- Инструкции `AGENTS.md` и `GIGACODE.md` (фича 6 дорожной карты) рядом с
  `DEVASSIST.md` и `DEVASSIST.local.md`; приоритет по возрастанию: `AGENTS.md` →
  `GIGACODE.md` → `DEVASSIST.md` → `DEVASSIST.local.md`, правило приоритетов — в
  системном промпте.
  - Те же файлы в подкаталогах подключаются, когда агент впервые успешно работает
    с путём внутри каталога, и действуют до `/clear`/`/resume`; `node_modules`,
    `.devassist` и исключённое `.gitignore` пропускаются.
  - Симлинк на уже прочитанный файл не дублируется; общий лимит 30 000 символов на
    каталог (место — сначала приоритетным, не поместившийся файл указывается путём).
  - `NestedInstructions`, `Tool.paths` (по умолчанию — поле `path`).

## [0.5.0] — 2026-10-09

### Added
- Окно контекста модели по замеру: `devassist --test-context <модель>` прощупывает
  лимит пробными запросами с ответом в один токен (калибровка по реальному
  `prompt_tokens`, подсказка из текста отказа, типовые размеры окон, бисекция;
  максимум — 256K) и сохраняет консервативный результат в `~/.devassist/models.json`.
  Окно незамеренной модели замеряется автоматически при запуске, `/model` и
  продолжении чата с другой моделью. `LLMProvider.measure_prompt`/`supports_measure`,
  `PromptTooLong`, `llm/context_probe.py`, `llm/model_windows.py`,
  `Agent.context_window`/`context_budget`.
- Автодополнение аргумента `/model`: меню доступных чат-моделей с их окнами
  (список загружается в фоне при старте REPL); `/model` без аргумента показывает
  этот список.
- Модель — часть сохранённого чата: `/model` сразу сохраняет её в чат, `/resume`,
  `-c`, `-r` делают текущей модель чата (явный `-m` её перекрывает).
- Сохранение чатов (фича 4 дорожной карты): диалог автоматически сохраняется после
  каждого хода (в том числе прерванного) в `.devassist/chats/<id>.json`:
  - `/resume` (алиас `/chats`) — селектор чатов: стрелки, PgUp/PgDn, Home/End,
    поиск по мере набора, у выбранного — начало последнего ответа, id и модель;
    `/resume <id>` — по id или его началу; после выбора показывается последний
    обмен репликами;
  - `-c`/`--continue` — продолжить последний чат, `-r`/`--resume [ID]` — выбранный
    (без ID — селектор); работают и с `-p`;
  - `--no-save` и переменная `DEVASSIST_SAVE_CHATS=0` — не сохранять;
  - `ChatStore`/`ChatRecorder` (`agent/chat_store.py`), `Agent.reset(conversation)`,
    `Config.save_chats`.
- Остановка при зацикливании (фича 2 дорожной карты): если модель повторяет один
  и тот же вызов инструмента (имя + аргументы), а между повторами не было
  изменений, на 3-м повторе она получает предупреждение, 4-й не выполняется и ход
  останавливается (`stop_reason="tool_repeats"`, `Config.max_tool_repeats`).
- Индекс проекта для больших кодовых баз (фича 3 дорожной карты):
  - файлы и определения (классы, функции, методы, типы, константы, заголовки
    Markdown) в `.devassist/index/` (SQLite); Python разбирается через `ast`,
    JS/TS, Go, Rust, Java, Kotlin, C#, Ruby, PHP, C/C++, shell — шаблонами;
  - инкрементальное обновление перед каждым запросом (перечитываются только
    изменённые файлы);
  - построение при запуске REPL, если индекса нет: ввод доступен после
    построения, Esc/Ctrl+C отменяет его (сделанное сохраняется и достраивается
    при следующем запуске), набранный текст переносится в строку ввода;
  - инструменты `find_symbol` (где определено имя) и `file_outline` (оглавление
    файла с номерами строк, сводка по каталогу);
  - команда `/index [rebuild]`.
- Учёт `.gitignore` (вложенные файлы, отрицания, `.git/info/exclude`) в
  `find_files`, `search_content`, дереве проекта и индексе.
- Нормальный терминальный интерфейс (фича 1 дорожной карты):
  - ответ модели форматируется как Markdown во время стрима (заголовки, списки,
    таблицы, подсветка кода) — готовые блоки печатаются окончательно, растущий
    блок перерисовывается внизу экрана;
  - анимированные индикаторы ожидания модели (и в `--no-stream`) и работы
    инструмента с прошедшим временем;
  - строка ввода: автодополнение слеш-команд с описаниями, многострочный ввод
    (`\` + Enter, Alt+Enter), история ввода в `.devassist/history`, подсказки из
    истории, статус-строка (модель, заполнение контекста, потрачено токенов, `-y`);
  - Esc прерывает ход (и запущенную команду), как Ctrl+C; Esc Esc очищает ввод,
    сохраняя черновик в истории; текст, набранный во время хода, переносится в
    следующую строку ввода;
  - `/help` — таблица команд и клавиш; итог хода с длительностью; длинный вывод
    команд показывается сокращённо (начало и конец).
- Инструмент `ask_user`: агент задаёт до 4 вопросов посреди хода — «Вопрос i из N»,
  варианты с подробными описаниями, множественный выбор, свой ответ; меню со
  стрелками, Esc — отказаться (агент решит сам). `AgentEvents.ask_user`,
  `ToolContext.ask_user`.
- Вложенные pydantic-модели в параметрах инструментов: `$ref` подставляется в схему.
- События `AgentEvents.on_tool_start`/`on_tool_end`; `TurnStats.duration_s`;
  `Agent.context_tokens`, `Agent.billed_tokens`, `Agent.config`.
- Чтение `DEVASSIST.local.md` (личные инструкции проекта).
- `docs/ANALYSIS.md` — анализ кодовой базы и дорожная карта.
- Переменная `DEVASSIST_CONTEXT_TOKENS`; коды возврата одноразового режима (130 при Ctrl+C).

### Changed
- Новый стартовый экран: слева пиксельная ракета среди звёзд, справа крупное
  название, версия, модель и проект (`ui/banner.py`); подпись под названием убрана.
- Индикатор ожидания — ракета `➤`, пролетающая через строку с мерцающим следом
  пламени и гаснущими искрами (`ui/spinner.py`, кадр 110 мс).
- Бюджет истории считается от окна текущей модели (90% от «окно минус 8K на
  ответ») за вычетом системного промпта и схем инструментов, а не фиксированные
  60 000; `DEVASSIST_CONTEXT_TOKENS` теперь явное переопределение (без него —
  по окну модели), `Config.context_budget_tokens` по умолчанию `None`.
- `--list-models` и `LLMProvider.list_models` — только чат-модели (`type == "chat"`).
- Одноразовый запуск (`-p`) теперь сохраняет чат — его можно продолжить через `-c`.
- `/clear` начинает новый чат; прежний остаётся сохранённым.
- Отказ в подтверждении больше не считается неудачным вызовом и не приближает
  остановку по серии ошибок; повтор уже отклонённой в этом ходе операции
  отклоняется без нового вопроса.
- `LoopGuard.after_tool` принимает `ToolOutcome` вместо `bool`; новый
  `LoopGuard.before_tool`.
- `on_stream_start`/`on_stream_end` вызываются и в непотоковом режиме (ожидание ответа).
- Подтверждение операций — компактная строка с описанием вызова.
- Минимальная версия `prompt_toolkit` — 3.0.43.
- Проект переведён на [uv](https://docs.astral.sh/uv/): `uv.lock`, dev-зависимости
  в `[dependency-groups]`; `requirements*.txt` удалены.
- Реорганизация кода под дорожную карту (см. `docs/ANALYSIS.md`): пакеты
  `project/` (Workspace, обход файлов, инструкции) и `cli/` (REPL, реестр
  слеш-команд); ядро агента общается с UI через события `AgentEvents`;
  история диалога — сериализуемый `Conversation`; ограничители цикла — `LoopGuard`.
- `.env` больше не записывается в окружение процесса, а `GIGACHAT_*` удаляются из
  окружения запускаемых команд. Скрипты, которые полагались на наследование
  ключа дочерними процессами, должны получать его явно.
- История укладывается в бюджет контекста по оценке токенов
  (`DEVASSIST_CONTEXT_TOKENS`) вместо лимита в 80 сообщений.
- `read_file` отдаёт не более 1000 строк / 60 тыс. символов за вызов с подсказкой
  продолжения; диапазон строк работает для больших файлов.
- `list_dir` и дерево проекта показывают скрытые файлы (`.github`, `.gitignore`).
- В статистике хода раздельно показаны размер контекста и потраченные токены.
- Ctrl+C на приглашении REPL больше не завершает программу (выход — Ctrl+D или `/exit`).
- Системный промпт советует искать определения через `find_symbol`/`file_outline`
  и читать только нужный диапазон строк; для крупного проекта вместо неполного
  дерева — подсказка про инструменты обзора.

### Security
- `write_file`/`edit_file` отказываются писать в служебную папку `.devassist/`
  (индекс, история ввода, чаты) — ещё до запроса подтверждения; проверка не зависит
  от регистра имени (`.DEVASSIST` на macOS/Windows).

### Fixed
- Падение REPL при записи/редактировании файла по пути вне проекта.
- Битая история после Ctrl+C во время работы инструмента.
- Дублирование текста ответа при обрыве соединения посреди потока.
- Падение REPL на сетевых ошибках, не обёрнутых в `GigaChatError`
  (`ReadError`, `ProxyError`, не-JSON ответ и др.).
- Недетерминированный приоритет `.env` проекта и текущей папки; traceback на
  некорректных `GIGACHAT_TIMEOUT`/`DEVASSIST_TEMPERATURE`.
- Выход за песочницу: `find_files` с `../`, `git diff --output=…`/`--no-index`,
  чтение файлов по симлинкам наружу в `search_content`.
- `git branch -D/-m` выполнялись без подтверждения; несуществующая подкоманда `stash-list`.
- Зависание команд, ожидающих ввод (`cat`, `git commit` без `-m`), и команд с
  фоновыми процессами; бинарный вывод команд; потеря конца длинного вывода.
- `search_content`/`find_files` обходили `node_modules` и т.п. целиком; читали
  бинарные и огромные файлы; `max_results` не ограничивался.
- Вывод ESC-последовательностей из ответа модели и вывода команд в терминал.
- Ложная классификация `rm <файл на r/f>` как опасной команды.

## [0.1.0] — 2026-06-24

### Added
- Первый релиз. Локальный CLI-агент для программирования на базе GigaChat.
- Инструменты: чтение/запись/редактирование файлов, `list_dir`, `find_files`,
  `search_content`, `run_shell`, безопасное подмножество `git`.
- Агентный цикл с function calling, потоковый вывод (SSE), REPL и одноразовый режим.
- Слой безопасности: песочница по корню проекта, подтверждение опасных операций,
  классификация риска команд.
- Контекст проекта: дерево файлов + файл-память `DEVASSIST.md`.
- Терминальный UI на rich: диффы, панели, сводка по шагам/токенам.
- Тесты: офлайн-юниты, live-тесты GigaChat (маркер `live`), сквозной smoke-тест.
